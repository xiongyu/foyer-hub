# Foyer Hub 插件中心规范

**状态：已确认的首版开发规则，尚未实现。** 当前宿主能发现本机已安装且显式启用的 Python 插件，校验依赖，在启动失败或停止宿主时回收资源。在线安装、在线卸载和运行中切换单个插件是下一阶段的交付要求。[当前插件 API](plugins.md)

验收时，在模拟通话中升级设备插件，网页应显示“等待通话结束”。用户能在旧版本上挂断；挂断后后端移交设备连接，核验新版，再更新运行版本。整个过程宿主保持运行，无关插件、会话和网页连接继续工作。

## 插件仓库与分发边界

| 来源 | 谁能发现和安装 | 规则 |
| --- | --- | --- |
| 公开索引 | 可公开浏览；由已认证的后端管理员批准安装 | 索引只列公开插件及其制品引用。刷新仅更新可发现版本，不安装、不升级。索引不可用时使用最近一次有效缓存。 |
| 私有来源 | 获得相应来源授权的后端管理员 | 按来源鉴权。私有插件 ID、地址、清单、版本、依赖快照、安装记录和访问令牌不得出现在公开索引、公共包源、公开 CI、普通客户端或外部诊断中。 |
| 本地离线包 | 已认证的后端管理员 | 支持导入私有 wheel 与锁定的离线依赖，执行相同的校验、确认与激活流程。日常值守和恢复已安装版本不依赖外网。 |

物业协议的源代码、格式说明、测试向量和实际制品仅在授权环境保存和分发。公开宿主只依赖版本化能力契约，公开源码、安装包和演练环境均须能独立使用。普通前端只看通用能力与业务状态；授权管理员才可在自己的后端查看私有安装详情。

## 管理操作与安装事务

PC 插件中心提供“发现”“已安装”“手动安装”。后端鉴权并执行安装、启用、停用、升级、回退和卸载。界面分别显示期望状态、已安装版本、实际运行版本，以及等待或失败原因。PC、手机和平板共享同一后端的安装状态。兼容性按**后端**的 OS、CPU、Python ABI、宿主 API 和原生 SDK 判断。

1. **预览。** 只读静态清单，不导入插件。展示来源与发布者、固定版本和制品摘要、能力与依赖变化、数据版本、热更新策略及影响的会话。Git 标签或分支须解析为固定提交；另行验证实际安装制品的 SHA-256，摘要必须来自可信渠道或由已信任的发布者密钥签名。
2. **确认与暂存。** 确认绑定操作者、来源、插件、固定制品、操作和当前配置修订号。任一项变化或确认过期，都要重新预览。首版只接收预构建 wheel 和锁定依赖，不在宿主环境执行仓库安装脚本。依赖缺失、版本不兼容、依赖环或提供者冲突时，在启动任何设备 I/O 前拒绝操作。
3. **激活。** 每个版本保存在独立、不可变的发布目录。候选在不持有真实设备写权的执行环境中验证。下载和校验成功只改变安装状态；只有接管通过并发布新路由后才显示“已生效”。状态按修订号原子持久化，两个管理窗口不能相互覆盖已确认的操作。

## 不停机切换与卸载

| 环节 | 宿主必须保证 |
| --- | --- |
| 计算影响范围 | 检查提供者、必需消费者和契约主版本。不兼容的依赖组一起切换或拒绝操作。可选依赖消失时，只将对应功能标为不可用。 |
| 等待在用资源 | 每次调用、通话、媒体流和控制请求绑定一个运行代次，调用双方持有资源占用记录，直到工作确实结束。进入维护后拒绝受影响的新写操作；允许既有会话挂断和释放资源。超时或发送取消不等于资源已释放。 |
| 移交独占资源 | 会话排空后才撤销旧代写权，移交住户身份、端口和 SDK 句柄。任一时刻最多一个有效写入者，旧代的引用和迟到回调不能再驱动设备。若交接需要短暂停止接收新来访，网页明确显示该能力的维护窗口。开门、呼梯等结果未知的指令不得因升级、取消或恢复而自动重发。 |
| 处理失败 | 预检失败继续运行旧版。已移交后候选失败，先释放候选资源，再恢复并核验上一已知良好版本；恢复失败标为离线。记录事务阶段，断电后据此恢复。代码回退不回滚用户数据；不兼容的数据迁移需另行备份与确认。 |
| 停用与卸载 | 停用保留安装与配置。卸载先预览受影响依赖和会话，再按依赖逆序撤销路由、订阅、任务和 UI 贡献；清理完成才显示“已卸载”。配置和业务数据默认保留，永久清理是独立操作。 |

可热切换的插件必须能独立回收执行环境；Python 首版优先验证按代次隔离的工作进程与宿主管理的契约代理。无法独立换代的原生库须在清单中声明“待重启”或“随宿主升级”，并说明原因。仅该插件受限，不能阻止其他插件热更新。核心管理、授权和安全恢复入口由宿主保留；恢复模式可暂停业务插件并回退故障版本。

## 首批验收顺序

1. **两个纯模拟插件。** B 正在调用 A，管理员更新或卸载 A。旧调用正常收尾，切换后新调用只进入新版；无关插件和网页连接保持可用。
2. **坏包、并发和断电。** 候选校验或激活失败仍可使用旧版；过期确认不能覆盖新设置；切换中模拟断电后能恢复，控制动作重放次数为零。
3. **插件目录和 PC 管理页。** 分别走通公开发现与在线安装、授权私有安装、离线导入、停用、回退和卸载。普通客户端看不到私有条目。索引断网时已装插件继续值守，卸载后配置仍可恢复。
4. **独占设备和平台差异。** 先用模拟设备验证通话中等待、挂断后切换、双重注册次数为零，再进入授权现场测试。PC、Linux 和有线 Android 分别记录可热切换、需短暂维护、需随宿主升级的能力。

设计参考了 LittleDock 的[安装管理器](https://github.com/xiongyu/littledock/blob/7aa21989784eda24d8427d293098224155f949f0/backend/src/plugin-system/manager.ts)、[资源作用域](https://github.com/xiongyu/littledock/blob/7aa21989784eda24d8427d293098224155f949f0/backend/src/plugin-system/lifecycle.ts)和[热切换回归用例](https://github.com/xiongyu/littledock/blob/7aa21989784eda24d8427d293098224155f949f0/backend/tests/plugins.test.mjs)。Foyer Hub 的验收以本规范和自身测试为准。
